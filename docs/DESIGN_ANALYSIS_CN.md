# NekoLink 深度设计分析与全局作用 ฅ^•ﻌ•^ฅ

## 1. 项目定位：为什么需要 NekoLink？

在现代网络环境中，传统的 VPN 和隧道协议（如标准 WireGuard UDP）经常面临严重的 **DPI（深度包检测）识别** 和 **QoS（服务质量）限速**。UDP 协议（Protocol 17）常常被防火墙视为次要流量，在拥塞或特定的策略下会被优先丢包或限制频率。

**NekoLink** 的核心作用是：**“在不牺牲 WireGuard 高性能的前提下，通过协议伪装与隐蔽信令，将隧道流量完全‘猫娘化’，从而穿透复杂的网络限制。”**

---

## 2. 核心隐蔽策略 (Stealth Strategies)

NekoLink 不仅仅是 WireGuard 的一个实现，它围绕“隐蔽性”构建了多层防御：

### 2.1 协议跨界：从 UDP 到任意 Raw IP
这是 NekoLink 最引以为傲的魔法。通过 `ip` 模式，流量可以直接运行在 1 到 255 之间的任何 IP 协议号上。
- **作用**：让防火墙看到的既不是 TCP 也不是 UDP，而是未知的原始 IP 流量，极大增加了识别难度。
- **信令复用**：在 `ip` 模式下，连最基础的公钥交换（Signaling）也完全复用该 Raw IP 协议，物理链路上没有任何 UDP 端口开放喵。

### 2.2 传输变幻：TCP 与 Fake-TCP
- **Native TCP**：内置了类似 Mullvad 的 TCP 驱动，将数据包封装在标准 TCP 流中，稳定穿透那些“UDP 杀手”网络。
- **Fake-TCP**：通过调用侧车组件（Sidecar），模拟 TCP 的三次握手状态机，骗过那些检查连接状态的中间盒喵。

### 2.3 动态信令 (Signaling Evolution)
在 **3.3.1** 版本中，信令系统更加智能：
- **服务器固定，客户端随机**：作为客户端时不再占用固定端口，像普通流量一样使用动态端口，减少了被扫描到的风险。
- **Smart Halt (智能停机)**：握手成功后，信令通道会进入深度休眠，物理链路上不再产生任何握手外的控制包，真正做到“随风潜入夜”喵。

---

## 3. 架构设计：模块化协作

NekoLink 采用了 **“核心轻量化，控制集中化”** 的分层设计：

### 3.1 `nekolink-core` (核心引擎)
基于 Boringtun 深度定制的数据平面，负责最繁重的加密解密与封包任务。它不关心协议号，只负责把 IP 包变成魔法密文喵。

### 3.2 `nekolink-cli` (执行终端)
每个隧道实例的真正运行者。它专注于单一网卡的维护，通过标准 TUN 接口与系统通讯。

### 3.3 `nekolink-ctl` (智能中枢)
这就是 NekoLink 的“大脑”。
- **多实例并发**：并行加载并启动所有 JSON 配置。
- **侧车调度**：根据模式自动拉起 `udp2raw` 或其他辅助组件。
- **信令编排**：负责 PSK 验证、自动公钥交换、MTU 自动探测以及 SOCKS5 服务端的启停。

### 3.4 `neko-link.sh` (交互之魂)
为“零基础”主人设计的交互层。通过图形化的 Shell 向导，将复杂的 JSON 配置抽象为简单的填空题喵。

## 4. 用户体验与组网理念

### 4.1 安全优先的“断连保护”
NekoLink 默认不修改全局路由表 (`Table=off`)。
- **设计初衷**：防止因为配置错误（如全流量代理导致的死循环）将本地机器彻底搞挂。用户可以精确控制哪些流量走隧道，甚至只通过 SOCKS5 代理特定应用。

### 4.2 高度灵活的 SOCKS5 系统
在 **3.3.1** 中引入了全局环回接口。
- **设计初衷**：不仅是为了自己用，更是为了让容器、虚拟机甚至局域网内的队友也能享受到魔法。通过独立开关，主人可以精准掌控“谁能用我的魔法”喵。

---

## 5. 总结

NekoLink 的设计哲学是：**“底层硬核，表层温柔”**。

它在底层使用了 Rust 最先进的异步/多线程技术（如 `tokio` 与 `boringtun`）确保万兆级别的吞吐能力；而在表层，它通过隐蔽的自定义协议和萌化的交互界面，让每一个网络节点的部署都变得既有趣又高效喵！
